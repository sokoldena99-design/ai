# Диалог — личный ИИ-чат

Приватный ChatGPT-подобный чат с локальной большой языковой моделью. История разговоров хранится в SQLite. Запросы к ИИ обрабатываются моделью Ollama на вашем компьютере или сервере: облачные ИИ, внешние API и API-ключи не используются.

## Запуск на компьютере

Требуются Node.js 22.13+ и Ollama.

1. Установите Ollama с официального сайта: <https://ollama.com/download>.
2. В PowerShell загрузите модель:

   ```powershell
   ollama pull qwen3:4b
   ```

   Для компьютера с 8 ГБ оперативной памяти используется компактная модель Qwen3 4B. Она работает локально, но на процессоре отвечает медленнее облачного ChatGPT.
3. Запустите локальный сервер Ollama с отключёнными облачными моделями:

   ```powershell
   $env:OLLAMA_NO_CLOUD = "1"
   ollama serve
   ```

   В другом PowerShell загрузите модель командой из шага 2.
4. В другом окне терминала, в папке проекта, выполните:

   ```powershell
   node server.js
   ```

5. Откройте <http://127.0.0.1:8000>.

Если установили другую модель, задайте её имя в переменной `OLLAMA_MODEL`. Адрес Ollama настраивается переменной `OLLAMA_URL`. Порт сайта задаётся через `PORT`, адрес прослушивания — через `HOST`. По умолчанию Node.js слушает только `127.0.0.1`; для контейнера используйте `HOST=0.0.0.0`.

Файл истории чатов создаётся по пути `data/chat.db`. Сохраняйте папку `data` при резервном копировании.

## Развёртывание на хостинге

Docker Compose поднимает веб-сайт, Ollama и отдельную загрузку модели. Модель и история хранятся в отдельных постоянных Docker volumes.

1. Установите Docker и Docker Compose на сервер.
2. Скопируйте проект на сервер и задайте настройки:

   ```powershell
   Copy-Item .env.example .env
   ```

3. Запустите из папки проекта:

   ```powershell
   docker compose up -d --build
   ```

   При первом запуске Docker скачает Ollama, модель Qwen3 4B и соберёт сайт. Облачные модели Ollama отключены.
4. Контейнер сайта доступен на порту `8000` только с самого сервера. Подключите свой HTTPS reverse proxy (например, Caddy, nginx или прокси хостинг-провайдера) к `127.0.0.1:8000`. Сам Ollama наружу не публикуется.

`APP_PORT` в `.env` меняет локальный порт сайта; `OLLAMA_MODEL` — модель, которую скачивает Docker. Серверу нужно место для Docker-образов, файла модели (несколько ГБ) и истории чатов, а также достаточно памяти, чтобы запустить Ollama. Docker volumes сохраняются после обновления приложения и `docker compose down`; не запускайте `docker compose down -v`, если хотите сохранить модель и историю. На хостинге без Docker можно отдельно запустить Ollama и Node.js: задайте `HOST=0.0.0.0`, `OLLAMA_URL=http://127.0.0.1:11434`, `PORT` в настройках процесса и постоянное хранилище `data`.

Приложение рассчитано на личный чат, а не на несколько изолированных аккаунтов: все подключённые пользователи видят историю этого сервера. Не открывайте порт Ollama `11434` в интернет. Для публичного сайта обязательно настройте HTTPS и авторизацию на reverse proxy; для разных пользователей сначала добавьте в приложение отдельные аккаунты и изоляцию их истории.

## Возможности

- Чат с генерацией ответа в реальном времени и контекстом предыдущих сообщений.
- Несколько диалогов с сохранением истории после перезапуска.
- Форматирование ответов и блоки кода.
- Удаление диалогов.
- Полностью локальная модель без API-ключей.

## API

- `GET /api/health` — состояние сервера и доступность выбранной модели.
- `GET /api/conversations` — список диалогов.
- `POST /api/conversations` — создать диалог с JSON `{ "id": "<UUID>" }`.
- `GET /api/conversations/{id}/messages` — история диалога.
- `DELETE /api/conversations/{id}` — удалить диалог и сообщения.
- `POST /api/chat` — отправить `{ "conversationId": "<UUID>", "message": "Привет" }`; ответ передаётся событиями Server-Sent Events.
